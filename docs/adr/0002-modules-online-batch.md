# ADR-0002: 온라인과 배치를 분리한 멀티모듈

- 상태: 확정 (2026-10-01)

## 맥락

금융권 시스템은 온라인(실시간 거래)과 배치(야간 대량 처리)를 별도 서버로 운영하는 게 일반적이다. 배치가 CPU·DB를 크게 쓰는 동안 온라인 응답이 느려지면 안 되기 때문이다.

## 대안

- **애플리케이션 하나에 API와 배치를 함께**: 단순하지만, 배치 실행 중 온라인 지연을 분리할 수 없고 배포 단위도 하나로 묶인다.
- **시뮬레이터와 PG가 전문 클래스까지 공유**: 구현은 빠르지만, 양쪽이 같은 버그를 공유하면 테스트가 통과해도 실제 연동에서 깨진다.

## 결정

```
codec        고정길이 필드 인코딩/디코딩 (MS949, N/AN 패딩, 바이트 경계 처리)
core         도메인, MyBatis 매퍼, 공통 서비스
online-api   승인·취소 REST API + 카드사 전문 클라이언트     (Spring Boot 앱)
batch        정산 배치 잡                                  (Spring Boot 앱)
simulator    가상 카드사: 전문 서버 + 매입 파일 생성기         (독립 앱)
```

- `simulator`는 `codec`만 의존한다. **전문 레이아웃은 PG와 시뮬레이터가 각자 정의**하고, 양쪽 모두 [02-message-spec.md](../02-message-spec.md)의 골든 샘플로 테스트한다.
- `online-api`와 `batch`는 같은 DB를 쓰지만 별도 프로세스로 실행한다.

## 결과

- 실제 금융권 구조(온라인/배치/대외계)와 비슷해서 면접에서 구조를 설명하기 쉽다.
- 모듈 경계를 잘못 잡으면 `core`가 비대해진다. `core`에는 두 앱이 실제로 함께 쓰는 것만 둔다.
