# ADR-0004: 금액·수수료 계산 규칙

- 상태: 확정 (2026-10-01)

## 맥락

금액 계산에서 1원이라도 합계가 맞지 않으면 금융권에서는 장애로 취급한다. 반올림 방식과 절사 위치를 명시적으로 정해야 한다.

## 대안

- **거래마다 수수료를 계산해 합산**: 거래별 수수료가 바로 나오지만, 거래마다 원 미만을 버리므로 합계가 작아진다. 소수부가 고르게 분포한다면 거래당 평균 0.5원, 하루 100만 건이면 약 50만 원 차이다.
- **`double`로 계산**: 0.1 + 0.2 ≠ 0.3 같은 이진 부동소수점 오차가 생긴다. 금액에는 쓰지 않는다.

## 결정

- 금액은 원 단위 정수: Java `long`, DB `NUMBER(15)`.
- 요율과 곱셈은 `BigDecimal`. 요율은 `NUMBER(7,6)`.
- **수수료 = 정산 합계(거래 합계 − 취소 합계) × 요율, 원 미만 절사.** 정산 행 단위(가맹점, 매입일, 요율)로 한 번만 절사한다.
- **부가세 = 수수료 × 0.1, 원 미만 절사.**
- 절사는 `RoundingMode.DOWN`(0 방향). 음수에서 `FLOOR`와 결과가 다르다 (−2.5 → DOWN −2, FLOOR −3).
- 거래별 수수료는 정산 수수료를 **최대 잉여 배분법**으로 나눈다. 동점은 `acquisition_record_id` 오름차순.
  - 배분의 기본값은 `FLOOR`로 잡는다 (2026-10-01 보완). 매입취소는 금액이 음수라 `DOWN`으로 잡으면 남은 금액이 음수가 될 수 있다. 예시는 [04-batch.md](../04-batch.md) 5장.

## 결과

- 정산 수수료 합계 = 거래별 배분 수수료 합계가 항상 성립한다 (검증 쿼리로 확인).
- 거래별 수수료를 단독으로 계산한 값과 배분된 값은 1원 차이가 날 수 있다. 가맹점 보고서에는 배분값을 쓴다.
